## 3. 为什么两个轨迹基线都 decline 打字

打字事件在检测器网格上是一串**定点按压**：一次按键的接触段里 x、y 是常数，
79.6% 的行是无接触行且 x=y=0 恰好。无条件序列生成器不知道要打哪个键 ——
它生成的「弦」是首个按键位置到末个按键位置的向量，而载体要求的是具体键盘坐标，
把两者对齐是没有意义的操作。实测：keystroke 有 19% 的事件在放置后需要压缩到不足一半尺寸
（p1 = 0.072），而其他四个动作 >99.7% 完全不缩放。这些格子测的会是这个变换，不是生成质量。

独立佐证：Diffusion-TS 的 keystroke **轨迹**模型的 discriminative 差距是 **0.379**，
是所有模型里最差的（其余轨迹模型 ≤0.024）。这个任务本身就不适合无条件生成器。

pyclick 同理拒绝，理由更直接：指针路径生成器没有路径可生成。

## 4. 「复现对了」的三层证据

### 4.1 环境层：Diffusion-TS 在作者自己的 Sines 上

| | discriminative | predictive |
|---|---|---|
| 论文 Table 1 | 0.006 ± 0.007 | 0.093 |
| 本复现 | **0.0108 ± 0.0061** | 0.1868 ± 0.0007 |
| real-vs-real 对照 | 0.0123 ± 0.0074 | 0.1859 ± 0.0007 |

discriminative 落在论文 1σ 内，且**低于 real-vs-real 对照** —— 后验分类器区分「生成 vs 真实」
比区分「真实 vs 真实」还弱。predictive 的绝对刻度与论文不同，但生成值与我们自己的地板差 0.0009，
结论一致。

### 4.2 生成器层：作者自己的指标 + real-vs-real 对照

| 模型 | 生成 vs 真实 | 对照 | 差距 |
|---|---|---|---|
| tap 轨迹 | 0.0117 | 0.0158 | **−0.004** |
| pinch 轨迹 | 0.0175 | 0.0150 | 0.003 |
| scroll 轨迹 | 0.0292 | 0.0225 | 0.007 |
| swipe 轨迹 | 0.0300 | 0.0058 | 0.024 |
| tap IMU | 0.0375 | 0.0217 | 0.016 |
| scroll IMU | 0.0658 | 0.0158 | 0.050 |
| pinch IMU | 0.0800 | 0.0242 | 0.056 |
| swipe IMU | 0.1325 | 0.0158 | 0.117 |
| keystroke IMU | 0.1692 | 0.0383 | 0.131 |
| keystroke 轨迹 | 0.4000 | 0.0208 | 0.379 |

**四个触控动作的轨迹模型全部落在数据自身的地板上**，所以它们的 FAR 就是 Diffusion-TS
在这个任务上的真实上限，不是没训好。

### 4.3 harness 层

四项检查（`verify_harness.py`），每个数据集都跑：载荷路由按 event_id 逐条核对、
真人事件逐字节不变、不该动的列与另一模态逐字节不变、无接触行保住 (0,0)、
声明的替换数与实际发生变化的事件数一致。全部 PASS。

外加往返重采样畸变实测（xy ≤ 0.035 px P95，IMU ≤ 0.006，通道 std 为 1.6–2.0），
以及放置诊断（缩放 p99 ≤ 2.95、最大 5.76，裁剪采样点 0）。

## 5. TTS-GAN 第一轮作废的记录

第一轮用 8,000–30,000 次迭代（作者发布值是 500,000），得到 FAR 中位 0.0008。
查根因发现生成的 IMU 是**白噪声**，且与预算严格单调相关：

| 动作 | 迭代数 | lag-1 自相关（真人 0.945–0.996） |
|---|---|---|
| tap | 30,000 | 0.850 |
| pinch | 20,000 | 0.522 |
| swipe | 15,000 | 0.482 |
| scroll | 15,000 | 0.479 |
| keystroke | 8,000 | 0.387 |

对照：Diffusion-TS 的 lag-1 是 0.951–0.993，与真人一致 —— 排除 harness 嫌疑。
第一轮整体保留在 `ttsgan_lowbudget/` 与 `ttsgan_budget_evidence.json`，
四倍预算重训的结果见 `04_imu_tts_gan/results/`。
