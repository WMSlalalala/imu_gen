# 基线 harness 审计与修复记录

五路独立审计 + 对抗验证。每一条都被验证者判定为**真实存在**，全部已修。
这份记录的用途是：论文里报的基线数字，必须能证明「基线差是方法本身差，不是我们跑错了」。

## 修了什么

| # | 位置 | 缺陷 | 会怎样歪曲对比 | 修法 |
|---|---|---|---|---|
| 1 | `hmog_baseline_common.rewrite_shard_arrays` | 轨迹替换丢掉载体的**零阶保持更新时机** | 真人笔画约一半的行重复上一行（swipe 0.504），基线每行给新点（0.041）；**单个标量就能完全分开**，swipe/scroll 的 FAR=0 测的是这个 | `apply_carrier_dispatch` 把载体的更新时机重新加回生成路径（修后 swipe 0.409） |

## 记录下来但**不修**的（是事实，不是缺陷）

- **pyclick 的 tap 退化成静止点**：库的 `midPtsCnt = max(|dx|,|dy|,2)`，tap 请求起终点重合 → 只有 2 个贝塞尔点。这是库的性质（它是为鼠标 A→B 写的），不是误用。表里如实标注。
- **Diffusion-TS 采样内部 clamp 到 [-1,1]**：作者代码 `p_mean_variance(clip_denoised=True)` 自带，不是我们加的。
- **TTS-GAN 迭代预算低于发布的 500,000**：五个模型、最长 512 步序列，发布预算等于几十小时一个模型。预算写在 `sweep_tts_gan.sh`，够不够由作者自己的 discriminative score 对照 real-vs-real 实测回答，不靠声明。
- **TTS-GAN 的多数 CLI 参数模型收不到**：`train_GAN.py` 本来就用默认形状构造 `Generator()`/`Discriminator()`，那些 flag 是从图像 GAN 代码库 fork 来的遗留物，两个模型根本不接受。我们只传模型确实接受的形状参数。
- **定长窗口往返重采样**：实测对真人事件的畸变 xy ≤ 0.035 px（P95）、IMU 平均 ≤ 0.0056（通道 std 为 1.6–2.0），可忽略。
- **信息量不对称**：基线在 70 个 train 用户的全部真人事件上训练，本方法只用受害者 5 条。已写进每个数据集的 `release.json` 的 `baseline_threat_model` 字段。

## 顺带发现的、关于论文自己方法的事实

20,000 个假 tap 载体里有 **13,014 个（65%）在检测器网格上没有任何位置更新** —— 整条 tap 就是一个由绑定目标决定的常数坐标，任何方法都只能输出它（pyclick 有 9,274 条与本方法逐位相同）。

在剩下 35% 上，本方法的重复行占比是 **0.660，真人是 0.908** —— **假 tap 报告的位置更新比真人多**。这是 7.6 节 F.1「tap 残差桥」的直接证据：残差桥不是在保留真人微移，是在制造真人不会有的位置更新。
