# 第三方开源基线：轨迹 ×2 + IMU ×2

给 direct100k 这套攻击评测配的**对照组**。四个基线全部来自别人已发表并开源的方法，
在**同一批载体、同一套检测器、同一个判据**下跑，唯一变化的是「假事件的信号是谁生成的」。

| 编号 | 通道 | 方法 | 出处 | 家族 |
|---|---|---|---|---|
| 01 | 轨迹 | pyclick HumanCurve | [patrikoss/pyclick](https://github.com/patrikoss/pyclick)，MIT | 手工（贝塞尔 + 高斯抖动 + 缓动） |
| 02 | 轨迹 | Diffusion-TS | [Y-debug-sys/Diffusion-TS](https://github.com/Y-debug-sys/Diffusion-TS)，ICLR 2024 | 扩散 |
| 03 | IMU | Diffusion-TS | 同上 | 扩散 |
| 04 | IMU | TTS-GAN | [imics-lab/tts-gan](https://github.com/imics-lab/tts-gan) | GAN（transformer） |

---

## 1. 为什么这样设计对比

检测器判的是「真人 vs 伪造」。要比的是**生成质量**，所以除了生成的通道之外，
任何一个可能影响判定的东西都必须逐位相同：

| 保持不变 | 说明 |
|---|---|
| 载体目标 | 同一批 100,000 个假事件的绑定目标（起终点、方向、时长、屏幕方向） |
| 采样点数 | 每条事件的行数不变（检测器网格 `PERIOD_MS = 10.0`） |
| 时钟 | 第 7 列 `elapsed` 原样保留 |
| 真人事件 | **逐字节不变**，检测器的正类完全相同 |
| 用户划分 | 固定 70 train / 10 dev / 20 test，用户不相交 |
| 检测器 | 同样 6 个（2 深度 + 4 经典），同样 20 epoch、同样 seed 42 |
| 判据 | FAR @ 开发集选出的 FRR=5% 阈值 |

轨迹基线**只改第 1、2 列（x, y）并重算 dx/dy**。接触、压力、指数、elapsed、可用性
不是「轨迹生成器」的产物，是派发事实，一律保留。IMU 基线只改 6 个惯性通道。

### 端点绑定（关键）

Diffusion-TS 和 TTS-GAN 都是**无条件**生成器：它们建模「这个动作长什么样」，
不知道手势该落在屏幕哪里。若直接把生成的笔画放在生成器自己给的位置上，
它就点不到载体要打的控件，检测器分开的会是**派发失败**而不是生成质量。

所以生成样本要绑到载体自己的端点上，用的是能做到这件事的**最小变换**：
一次旋转 + 一次等比缩放 + 一次平移，整段一起作用，无逐点形变、除屏幕边界外不裁剪。
当请求没有位移（tap）时退化为纯平移。

pyclick 天然接受起终点，直接给载体请求的端点（取整到像素）。

### 打字为什么被 pyclick 拒绝

打字事件在检测器网格上是「一串定点按压」——一次按键的接触段里 x、y 是常数，
中间没有 MOVE。指针路径生成器没有路径可生成，硬塞一条会变成打稻草人。
所以 pyclick 对 keystroke 返回 `None`，那 6 格保留载体原值。

**这恰好成了 harness 的正确性证据**：那 6 格的结果与源数据集**完全相同**（差 0.0000）。

学习型基线（Diffusion-TS / TTS-GAN）可以生成打字轨迹，做法是生成位置后
**在每个接触段内保持常数**（取段首值）——否则按住期间坐标漂移是 harness 的产物，
不是生成器的问题。

## 3. 「复现对了」的证据链

这套基线的意义完全取决于「基线差是因为方法本身，不是因为我们没跑对」。
所以每一个都有三层证据：

### 3.1 harness 层：`verify_harness.py`

1. **空替换 = 恒等**：让生成器原样返回载体自己的通道，重写结果与源**逐字节相同**。
2. **真人事件零改动**：与源数据集在全部真人行上逐字节比对。
3. **不该动的列没动**：轨迹替换后第 0/3/4/7/8 列与 IMU 全等；坐标无越界；结构字段全等。

另外 pyclick 数据集从 vendored 路径**重建一次**，与已评分的那份逐字节相同 → 构建是确定性的。

### 3.2 重采样层：往返畸变实测

生成器按动作固定长度训练（tap 16 / pinch 100 / swipe 176 / scroll 208 / keystroke 512），
样本再重采样到载体行数。这个往返对真人事件造成的畸变实测为：

| 动作 | xy 平均误差 | xy P95 | IMU 平均误差 |
|---|---|---|---|
| tap | 0.000 px | 0.000 | 0.0056 |
| pinch | 0.007 px | 0.001 | 0.0018 |
| swipe | 0.015 px | 0.035 | 0.0016 |
| scroll | 0.006 px | 0.000 | 0.0012 |
| keystroke | 0.000 px | 0.000 | 0.0024 |

IMU 通道自身标准差在 1.6–2.0 m/s² 量级，所以这一步基本不引入任何东西。

### 3.3 生成器层：作者自己的指标 + real-vs-real 对照

用 Diffusion-TS 仓库自带的 `discriminative_score_metrics` / `predictive_score_metrics`
（源自 TimeGAN）给每个生成器打分。**同时给一个 real-vs-real 对照**：
把真人窗口对半分，跑同样的指标。那是数据本身允许的下限。

- 生成器分数接近对照 → 拟合到位，它在检测器上的表现就是该方法的真实水平；
- 远高于对照 → 没训好，它的检测器分数**不能**当作该方法的上限来报。

指标本身的行为也已验证：两个明显不同的分布得 0.4875，同分布得 0.0125。

## 4. 已知的、写进论文时要说明的不对称

1. **信息量**：两个学习型基线在 **70 个 train 用户的全部真人事件**上训练
   （tap 4,306 条 / pinch 6,945 / swipe 6,959 / scroll 7,000 / keystroke 6,976），
   而本方法只用受害者本人 **5 条**。这个对比对基线是**偏宽松**的。
2. **样本复用**：每个基线生成 4,000 条样本填 20,000 个载体（平均复用 5 次）；
   本方法每条素材复用 40 次。基线的多样性高 8 倍。
3. **无条件生成**：Diffusion-TS / TTS-GAN 把容量花在了绝对位置上，
   而端点绑定会把绝对位置、旋转、缩放全部丢弃。这是「拿无条件生成器做有目标攻击」
   的固有代价，不是实现缺陷。
4. **训练预算**：Diffusion-TS 用作者 `Config/sines.yaml` 的 12,000 步；
   TTS-GAN 用作者 UniMiB 配方但迭代数按动作缩放（他们发布的 500,000 次在 5 个模型上不现实）。
   实际预算与收敛证据见各基线的 `results/quality.json`。
