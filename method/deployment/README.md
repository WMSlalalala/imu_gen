# 部署 / 注入（预留，本地另写）

> 本目录是**占位**。实际系统的部署与注入代码不在这里，由本地 Agent 另行撰写后填入。

## 这里将来放什么

把冻结发布版（`method/README.md` 阶段 1–7 的产物）接进移动 Agent、在真机上以「同一时间轴的触摸 + IMU」落地的那一层：

- **框架接管**：把移动 Agent（如 Mobile-Agent-E）的物理原语（tap/swipe/type/…）替换成本方法的动作，Agent 业务逻辑不改；
- **动作合成**：语义动作 → 时长（受害者素材）+ 方向 + 惯性窗口（缓存）+ 触摸供体，合成同一时间轴的事件包；
- **注入后端**：
  - App 内（不 root）——目标 App 自己按计划时间戳派发 MotionEvent，IMU 走 App 内的双源总线；
  - root——触摸经真实输入管线（uinput / sendevent），IMU 经 Frida hook 传感器交付函数；
- **落地验证**：注入后从设备读回，逐点核对触摸与 IMU 是否与计划一致、两者是否对齐。

## 为什么单独留出、且不在此仓库

1. 它是发布版的**下游应用**，不是生成方法本身——生成方法（阶段 1–7）在仓库根的已跟踪目录里，评测在 `../evaluation/`。
2. 它需要**真机联调**（注入通道、时钟对齐、Frida hook 都只能在设备上验），开发形态与本仓库（无数据、纯文本方法镜像）不同。
3. 因此这一层在本地独立开发与打包，成熟后再决定以何种形式并入或链接到本仓库。

- 在此之前，方法链路以 `../README.md` 的阶段 1–7 为准，部署层视为「计划中、未并入」。
